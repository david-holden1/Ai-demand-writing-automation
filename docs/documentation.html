01 — Objective

Project objective

AI Demand Writing Automation is a software engineering demonstration project focused on building an AI-assisted document workflow for evidence-backed demand letter drafting.

The platform is designed to reduce repetitive document review work by converting unstructured case material into structured information that can be searched, validated, and used within controlled AI generation workflows.

02 — Problem

The workflow problem

Case information is often distributed across medical records, invoices, reports, correspondence, and other documents. Manually reviewing those materials and assembling a coherent demand package can involve repetitive extraction and cross referencing.

The engineering challenge is therefore not simply generating text. The system needs to preserve relationships between generated claims and the underlying source evidence.

04 — Requirements

Functional requirements

Case Management Create and manage cases, case metadata, documents, processing status, and generated outputs.
Document Upload Support PDF and DOCX evidence uploads with metadata tracking and object storage.
Document Processing Extract text from digital documents and provide an OCR path for scanned or image-based documents.
Medical Extraction Structure relevant providers, diagnoses, treatments, procedures, dates, and treatment events.
Damages Extraction Organize supported medical expenses and other documented damages information.
Evidence Search Retrieve relevant document passages using semantic similarity and case-specific context.
Demand Letter Generation Generate structured drafts based on extracted facts and retrieved evidence.
Human Review Allow a human reviewer to inspect evidence, edit drafts, and approve final outputs.
Export Provide PDF and DOCX output paths for finalized documents.
Auditability Maintain processing metadata and workflow events to support traceability.

06 — Data Model

Core data entities

The initial data model is designed around cases, documents, extracted evidence, retrieval chunks, and generated outputs.

Entity Purpose Example Fields
cases Case-level information id, title, status, metadata
documents Uploaded source files case_id, file_name, type, storage_key
extractions Structured information document_id, entity_type, value, confidence
events Chronological case events case_id, event_date, event_type, description
chunks Retrieval-ready document segments document_id, text, embedding, metadata
generations AI-generated drafts case_id, version, status, content
audit_events Workflow traceability actor, action, timestamp, metadata
07 — Security

Security and privacy considerations

Access Control

Authentication and role-based authorization will restrict case and document access.

Data Protection

Sensitive documents should be encrypted in transit and at rest with controlled storage access.

Audit Logging

Important workflow and user actions should be recorded for traceability.

AI Guardrails

Generated outputs should remain grounded in retrieved source evidence and remain subject to human review.

09 — Roadmap

Implementation roadmap

Phase 1 — Foundation Repository structure, project documentation, application shells, environment configuration, and CI foundation.
Phase 2 — Backend FastAPI services, database models, migrations, case management APIs, and document upload flows.
Phase 3 — Document Intelligence PDF/DOCX parsing, OCR support, extraction pipelines, and structured case information.
Phase 4 — RAG Chunking, embeddings, pgvector indexing, retrieval, citations, and evidence-grounded responses.
Phase 5 — Multi-Agent AI LangGraph orchestration for extraction, timeline, damages, retrieval, drafting, and validation.
Phase 6 — Review Experience Human review interface, evidence inspection, editing, versioning, and document export.
Phase 7 — Deployment Containerization, infrastructure as code, cloud deployment, monitoring, and production hardening.
